taktwerk

taktwerk

taktwerk runs compiled models at a fixed step on Linux, beside or on a PLC, and exchanges their signals over OPC UA.

  • Models are FMI 3 or FMI 2 co-simulation FMUs, or plain C libraries described by a small descriptor. A model is size-generic; an instance binds its sizes.
  • The engine owns a process image. A real-time thread steps every model on absolute deadlines and reads a snapshot of the image at each tick; connectors sync the image with the outside in the background.
  • An own OPC UA server exposes every signal, the engine status and a heartbeat, so any OPC UA client doubles as a UI. taktwerk tui is one.
  • One TOML project file per engine describes models, instances, wiring and connectors.

What it is not

  • Not hard real time: a fixed step on stock Linux, with optional SCHED_FIFO, CPU pinning and locked memory. Jitter is measured on the target, never assumed.
  • Not a safety controller: models run in the engine’s process. Whoever consumes the outputs, typically the PLC, owns the safe state once the heartbeat stops (see Concepts).

Getting started

Install

taktwerk needs a Rust toolchain (1.88 or newer); the examples also need a C compiler.

cargo install taktwerk                   # installs `taktwerk` into ~/.cargo/bin

From a checkout: cargo install --path crates/taktwerk.

For a target other than the build host, see cross-building.

A project in four commands

taktwerk inspect plant.fmu --kind fmi           # dimensions, variables, shapes
taktwerk new plant.fmu --kind fmi -o plant.toml # scaffold a project file
taktwerk check plant.toml                       # load, resolve, bind; print the plan
taktwerk run plant.toml                         # until SIGINT or SIGTERM

new writes a project with one instance, every dimension at the model’s default, every input, output and tunable mapped to its default signal name, commented-out parameters, and an OPC UA server on opc.tcp://127.0.0.1:4840. Edit it, then check it: check loads every model, binds every dimension, resolves every signal and connects every connector, so it fails on anything run would fail on at init. It prints the plan:

  taktwerk.status     system     i32   scalar  -
  taktwerk.cycle      system     u64   scalar  -
  taktwerk.overruns   system     u64   scalar  -
  taktwerk.stale      system     u64   scalar  -

run logs to stderr (RUST_LOG filters, default info), stops on SIGINT or SIGTERM, prints a run summary and exits non-zero when a model or connector failed.

Watch and edit with the TUI

taktwerk tui opc.tcp://127.0.0.1:4840

The TUI is an OPC UA client of the engine’s own server. It shows status, heartbeat and counters, and every signal with its value and age. Keys: ↑/↓ or j/k select, PgUp/PgDn, Home/End (g/G) jump, Enter edits the selected input or tunable and Enter again writes it, Esc cancels, q quits. If the project changes namespace or system_prefix, pass --namespace and --prefix.

Concepts

Process image

The engine owns one value per signal, the process image. Every value lives in a typed buffer sized at init and never resized. Connectors write inputs and tunables and read outputs from their own threads; the cycle thread copies what it needs at its tick and stores outputs back. Each signal is locked only for one copy.

A signal has a direction:

directionwritten byread by
inputa connectorthe instances that consume it
outputthe instance that produces itconnectors, other instances
tunablea connector, while runningone instance, before its step
systemthe engineconnectors

Element types are f64, f32, i64, i32, i16, i8, u64, u32, u16, u8 and bool. A signal is a scalar or an array of any rank; matrices are stored row-major or column-major as the model declares.

Ticks and periods

One real-time thread wakes on an absolute deadline grid (clock_nanosleep with TIMER_ABSTIME) every engine.tick_ms. Each instance has a period of every ticks and is due at every tick whose number is a multiple of every, so all instances are due at tick 0.

Per tick:

  1. The external inputs and tunables of every due instance are copied from the image.
  2. If any of those inputs is stale, the tick is skipped (see stale inputs).
  3. Otherwise the due instances step in declared order. Each first copies its wired inputs, so it sees outputs stored earlier in the same tick.
  4. Outputs are stored, the heartbeat advances and the tick is published: connectors now see a complete, consistent set of outputs.

Model time is start_time + tick × tick_ms; an instance advances by its step size every × tick_ms per step. A tick that ends after the next deadline skips the missed slots and counts each in overruns; the tick counter stays contiguous, so after an overrun model time lags wall time by the skipped slots. Nothing on the tick path allocates.

taktwerk run --speed runs the same ticks faster than real time or unpaced, on engine time instead of the wall clock; see Simulation runs.

Instances and dimensions

A model is size-generic: its variables have symbolic shapes (u: f64[n], A: f64[nx, nx]) over named dimensions with an optional min, max and default. An instance references a model and binds every dimension, from the project file, from the model’s default, or "from-server" (the length a connector finds outside). The bound sizes are structural: they are fixed for the run, and a change needs a restart.

One model serves any number of instances. Whether one loaded library can host several is the model’s instances capability: multiple libraries keep their state per instance; for a single library (state in globals), each further instance loads a private copy of the file.

Parameters are set once before init. Tunables are set before init and change while running; a changed value is delivered before the instance’s next step. A tunable that no connector has written yet shows the model’s own start value after init, so writing one tunable never zeroes another.

Signals and wiring

An unmapped input, output or tunable v of instance i is the signal i.v. Mapping a variable in the project file names its signal:

  • An input mapped to a signal that some instance outputs is wired to it. It reads what the producer stored last: the same tick when the producer runs earlier in declared order, else the previous one. A wired input never goes stale.
  • An input nobody outputs is an external input, written by a connector.
  • Several instances may consume one signal.
  • A one-dimensional input may be composed element by element from scalar signals and elements of other instances’ outputs, each element wired or external as above; its value is the read-only signal i.v. A scalar input may take one element, x = "j.y[2]", the same way. See Project file.

Errors at init: two outputs on one signal, a tunable on an input or output signal, one signal used with two types, shapes or layouts, a mapping onto one of the engine’s own signals, or a signal name with [ or ] that is no element of another instance’s output.

Init

Before the first tick every instance is initialised once, in declared order. Its init sees its dimension lengths and parameters, its tunables as the image holds them (a connector’s write, else the start value), and its inputs as follows:

  • A wired input whose producer comes earlier in declared order holds the producer’s output as it stood after the producer’s init, so a library may seed its state from it.
  • A wired input whose producer comes later (a feedback loop) is zero.
  • An external input holds what a connector has written so far; if nothing yet, the model’s declared start, else zero. No first read is awaited and no age limit is checked at init.
  • The elements of a composed input follow the same rules, element by element.

Outputs written by an init are not stored in the image: connectors and other instances see outputs from tick 0 on, and every wired input is copied again before each step.

Stale inputs

Each external input may carry a maximum age, max_age_ms on the binding or engine.input_max_age_ms for all. Without one, an input never goes stale. With one, an input is stale when its last write is older than that at the tick, or when it was never written.

A stale input skips the whole tick: no instance steps, outputs and heartbeat are held, status becomes faulted and stale counts the tick. The fault is published at once. When inputs are fresh again the next tick runs normally and status returns to running.

An OPC UA client connector that loses its server stops writing its inputs, so they age and the engine turns them stale.

Heartbeat, status and the safety contract

The engine publishes its own signals under engine.system_prefix (default taktwerk):

signaltypemeaning
taktwerk.heartbeatu64advances once per tick whose outputs were published
taktwerk.statusi320 init, 1 running, 2 faulted, 3 stopped
taktwerk.cycleu64every tick, skipped ones included
taktwerk.overrunsu64deadline slots missed
taktwerk.staleu64ticks skipped for a stale input

Models run inside the engine’s process; there is no process isolation. Whoever consumes the outputs, typically the PLC, owns the safe state. It watches the heartbeat (map it to a PLC node with the OPC UA client) and falls back to its safe state when the heartbeat stops advancing or status is not 1. The heartbeat advances only on a tick whose outputs were published, so a held heartbeat means the outputs are not current.

Fail-stop

A model error (a non-success return code, or a failed init) terminates every instance and ends the run with that error; taktwerk run exits non-zero. A connector that fails beyond its own reconnect logic stops the run the same way. The engine does not retry: restart is the service manager’s job (see Running in production).

Every key in dims, parameters, inputs, outputs and tunables must name a dimension or a variable of that causality in the model.

dims

  • n = 3: a fixed length, checked against the dimension’s min and max.
  • n = "from-server": the length is discovered at init. The model needs a one-dimensional variable of shape [n]; the engine asks each connector for the length of the external item mapped to that variable’s signal. Today the OPC UA client answers for nodes in its map.
  • Unbound: the model’s default; without one, init fails.

parameters

Start values of parameters and tunables. Unset ones keep the model’s value: the FMU’s start value, or a raw descriptor’s start, zero without one.

  • A scalar takes a number or a boolean. Integers convert to floats; floats never convert to integers.
  • An array takes nested arrays, one level per dimension, first index outermost: A = [[1.0, 0.0], [0.0, 1.0]]. The engine stores it in the variable’s layout.
  • An array also takes one flat array of the full length, taken as already stored in the variable’s layout: A = [1.0, 0.0, 0.0, 1.0].

inputs, outputs, tunables

Each maps a variable to a signal name. Unmapped variables get <instance>.<variable>. An input binding is either a signal name or a table:

inputs = { y = "plant.y" }                                   # signal only
inputs = { y = { signal = "plant.y", max_age_ms = 50.0 } }   # with an age limit

max_age_ms overrides engine.input_max_age_ms for that input. It is refused on a wired input (one some instance outputs). When several instances consume one external signal, the explicit limits they set must agree; one explicit limit wins over the default. See Concepts for wiring rules.

A one-dimensional input may instead be composed element by element from a list with one source per element, in element order:

inputs = { y = ["plc.p", "est.mu", { signal = "plc.t", max_age_ms = 50.0 }, "est.v[1]"] }
  • name is a scalar signal of the input’s type: another instance’s scalar output (wired) or an external input, created when no one else uses it.
  • name[i] is element i, counted from 0, of another instance’s one-dimensional output of the input’s type.
  • { signal, max_age_ms } sets an age limit on one external element, as above.
  • The list’s length must equal the input’s bound length. Multi-dimensional and text inputs, outputs and tunables cannot be composed.
  • The composed value is the signal <instance>.<input>, read-only, stored each time the instance is about to step (and before its init), so a connector shows what the model received. taktwerk check lists every composed input with its element sources.

A scalar input takes one element the same way, without a list:

inputs = { n_st = "mpc.u[0]" }

It is a composed input of one element, with the same rules and the same read-only signal <instance>.<input>. A name with [ or ] that is not an element of another instance’s one-dimensional output is refused: no signal name contains brackets, so it never becomes an external input or a connector’s node mapping.

Changes

Everything in the project file is read at start. Structural changes (models, dimensions, wiring, connectors) need a restart. While running, only tunables change, through a connector.

Connectors

A connector syncs part of the process image with the outside. At init the engine builds each connector from its [[connector]] table, asks it for "from-server" lengths, builds the image and lets each connector verify its mapping (fail-closed). While running, connectors work on their own I/O threads; the cycle thread never waits for them.

Three kinds exist: the engine’s own OPC UA server, an OPC UA client and, in a build with the http feature, an HTTP API.

"sign" and "sign-encrypt" use the Basic256Sha256 policy. The server certificate is generated in pki_dir when a secure endpoint needs one. A user’s password comes from exactly one of password (inline) and password_env (the name of an environment variable); prefer password_env so no secret sits in the project file.

The server is open by default: anonymous, no encryption, all interfaces. On any network other than a closed machine network, bind it to one interface, turn off anonymous, add users and offer only secure endpoints.

Nodes

  • Every signal is a variable node with NodeId ns=<index of namespace>;s=<signal name>, for example ns=2;s=plant.y (the index is assigned by the server; read it from the server’s namespace array, or address the node by URI as nsu=urn:taktwerk;s=plant.y).
  • The browse path splits the name on . into folders under Objects: plant.y is Objects/plant/y, taktwerk.heartbeat is Objects/taktwerk/heartbeat.
  • Data types: f64 Double, f32 Float, i64 Int64, i32 Int32, i16 Int16, i8 SByte, u64 UInt64, u32 UInt32, u16 UInt16, u8 Byte, bool Boolean.
  • A scalar has ValueRank −1. An array has its rank and ArrayDimensions; matrix elements are sent in row-major order whatever the model’s storage layout.
  • A text signal is a scalar String node. A read gives the bytes up to the first NUL, decoded as UTF-8 (invalid sequences are replaced, not refused). A write takes a String of at most capacity − 1 UTF-8 bytes, copies it and zero-fills the rest; a longer one is refused with BadOutOfRange and one containing NUL with BadInvalidArgument, never truncated.
  • Outputs and system signals are read-only. Inputs and tunables are writable; a write goes to the image and is picked up at the next tick.
  • Every node follows each published tick, with the time the value was written into the image as its source timestamp. A value never written has status UncertainInitialValue.

Map

Each key is a signal of the image; each value a NodeId: ns=<index>;s=<id>, nsu=<uri>;s=<id> (the namespace is resolved by URI on every session), or the i=, g=, b= forms. Unmapped signals are not synced.

  • Inputs and tunables are read from their nodes, one bulk Read every sync_period_ms.
  • Outputs and system signals are written to theirs, one bulk Write per published tick.

Verification

Every session is verified before it syncs: the first at init, every reconnect again. For each mapped node the client reads DataType, ValueRank, ArrayDimensions, AccessLevel and the value, and refuses the session listing every mismatch:

  • the node exists and its DataType is the signal’s type (String for a text signal);
  • a scalar signal maps to a scalar node, an array signal to an array node with the same element count (from ArrayDimensions, or the current value when the server reports none);
  • the node is readable, and writable when the engine writes it.

A text signal maps to a scalar String node, typically a PLC STRING(n), and follows the server’s rules: a remote string longer than capacity − 1 bytes is not read into the image (the input ages, the problem is logged), and the PLC refuses an output longer than its own n. Array elements travel in the signal’s storage order. At init a refusal, or an unreachable server, stops the engine before the first tick. After a reconnect a refusal is logged and retried with backoff.

Reconnect and staleness

A lost session is closed and reconnected with exponential backoff. While disconnected, inputs are not written, so they age; with a max_age_ms the engine turns them stale and skips ticks until reads resume. An input read with a bad status, or a value that does not fit the signal, leaves that signal aging as well; the problem is logged once until it clears.

Stamp

stamp = "receive" stamps an input with the time the read response arrived: an input is as fresh as the last successful read. stamp = "source" uses the server’s source timestamp (or the receive time when it sends none). Servers that stamp a value only when it changes make a constant input look old under "source".

from-server

For an instance dimension bound "from-server", the client answers with the length of the node mapped to the dimension’s signal (its ArrayDimensions, else its current value’s length).

HTTP API

A build with the http feature (cargo install taktwerk --features ui for the web UI too) adds the http connector: the engine’s signals, values and events as JSON and server-sent events, and the web UI. taktwerk run --http 127.0.0.1:8480 adds one to any project, also with --no-connectors.

There is no TLS: keep listen on loopback, or on a network you trust.

Recording

A [[recorder]] keeps a lossless, per-tick history of selected signals, taken by the engine itself. OPC UA subscriptions sample and can miss ticks; a recorder sees every tick it is asked for. The cycle thread only copies the selected values into a preallocated ring buffer: no allocation, lock, I/O or wait. Everything else (files, compression, counters, remote pulls) happens on other threads, and a sink that falls behind loses rows instead of slowing the cycle.

[[recorder]]
id = "main"
signals = ["plant.*", "ctrl.u[*]", "ctrl.qp_flag"]

Two sinks

  • sink = "file" (the default): on an edge PC or a workstation. A drain thread per recorder writes gzipped CSV parts to the engine’s own disk (or a mounted stick). The ring is the drain’s slack.
  • sink = "buffer": on a PLC-class device with little RAM and flash. The engine keeps the last buffer_s seconds in RAM and writes nothing. taktwerk record on an edge PC beside it pulls the rows over OPC UA and writes the same files a file sink writes.

Both sinks serve their ring to pulls, so a file sink can be pulled as well.

What a row holds

One row every every ticks, at the ticks divisible by every: row n holds cycle n · every. Skipped ticks are recorded too (a stale input skips a tick; the row then holds the held outputs and taktwerk.status is 2). So consecutive rows always differ by exactly every cycles; any other jump is a loss.

A row is what the cycle holds after the tick is stored: outputs, composed inputs, system signals, and inputs and tunables bound whole to an instance, an input or tunable as the instance stepping most often holds it.

Selecting signals

signals lists patterns over signal names, in column order; a signal matched twice is recorded once.

  • * matches any run of characters, dots included; ? matches one character.
  • A trailing [*] takes every element of a one-dimensional signal, [i] element i (from 0). Without a selector an array is recorded whole.
  • An empty list (the default) records every output.
  • Each array element is one column, name[i], or name[i,j] with logical indices for a matrix. A text signal is one column.
  • A pattern that matches nothing recordable is an error. An external signal read only element by element (a source of a composed input) is not held whole and cannot be recorded; record the composed input <instance>.<input> instead.

Rotation and retention

A part closes, and the next one opens, when its compressed size reaches rotate.size_mb or it covers rotate.hours of engine time, whichever comes first. Rotation counts engine time, not wall time, so the same rows always split into the same parts.

Retention runs when a run opens and at every rotation, over all runs of one recorder (<dir>/<project>/<recorder>/). It deletes closed parts, oldest first, while the recorder’s parts together exceed retain.max_gb, and every closed part older than retain.days (by its modification time). The open part is never deleted; run.json and events.csv are kept.

Decimation and several recorders

every = 10 keeps one row per 10 ticks. A project may have several recorders, each with its own signals, every, sink and ring, for example a per-tick one for a few signals and a decimated one for everything. Their ids keep their directories, counters and pull nodes apart.

Sizing the ring

The ring holds buffer_s seconds of engine time: ceil(buffer_s / (tick_s · every)) rows, at least 2. A row takes one 8-byte word per numeric column, one per byte of a text column’s capacity, and two words of its own. taktwerk check prints both per recorder:

  recorder  sink    every  columns  ring rows  ring     dir
  main      file    1      8        60000      4.8 MB   records
  slow      buffer  10     3        600        24.0 kB  -

A ring larger than 4 GiB is refused. For a buffer sink, buffer_s is how long a puller may be away without a gap; for a file sink, how long the disk may stall without a drop.

Gaps and drops

Both show as a jump in the cycle numbers of a run, larger than every. They differ in where the rows were lost:

  • Dropped: the engine’s own file sink fell more than a ring behind the cycle (a stalled or slow disk). Counted in rows_dropped, logged as a dropped event with the cycles lost. Raise buffer_s, record fewer signals or a larger every, or use a faster disk.
  • Gap: a puller asked for rows the ring had already overwritten (the puller stopped or the network was down for longer than buffer_s). Counted in the engine’s gaps, logged as a gap event in the puller’s events.csv. Raise buffer_s on the engine.

A skipped tick is neither: its row is there, with taktwerk.status 2.

Reading a run

The standard library is enough: gzip and csv over every part in order, json for run.json. Every value arrives as a string; float() reads the float columns, NaN and inf included. This script is examples/recording/read_run.py:

"""Read one recorded run with the Python standard library alone.

Usage: python3 read_run.py <run-dir>
"""

import csv
import gzip
import json
import sys
from pathlib import Path


def rows(run: Path):
    """Yield every row of the run as a dict, parts in order, header lines skipped."""
    for part in sorted(run.glob("part-*.csv.gz")):
        with gzip.open(part, "rt", newline="") as f:
            try:
                yield from csv.DictReader(f)
            except EOFError:
                pass  # the open part of a running engine ends at its last flush


def main() -> None:
    run = Path(sys.argv[1])
    meta = json.loads((run / "run.json").read_text())
    every = meta["every"]
    n, gaps, last, prev = 0, 0, None, None
    for row in rows(run):
        cycle = int(row["cycle"])
        if prev is not None and cycle != prev + every:
            gaps += 1  # rows lost between prev and cycle
        prev, last, n = cycle, row, n + 1
    print(
        f"{meta['project']}/{meta['recorder']}: {n} rows, tick {meta['tick_s']} s, "
        f"every {every}, {gaps} gaps"
    )
    print("last row:", last)
    with open(run / "events.csv", newline="") as f:
        for e in csv.DictReader(f):
            print(f"event {e['cycle']} {e['kind']} {e['source']}: {e['detail']}")


if __name__ == "__main__":
    main()

Reproducible runs

taktwerk run --cycles N stops the engine after N ticks with a stop event cycle limit reached, at any speed; --speed max runs it unpaced and loses no row. Two runs of a deterministic project (no external inputs, no edits while it runs) give byte-identical parts and the same events.csv; run.json differs in run_id, engine_run and the UTC fields. taktwerk.overruns counts missed deadlines, which depend on the machine’s load; leave it out of signals when parts must match.

taktwerk run examples/recording/project.toml --cycles 200 --speed max --no-connectors

Remote recording

taktwerk record pulls one recorder of a running engine over OPC UA and writes the run files on the host it runs on, until SIGINT or SIGTERM. Run it on an edge PC beside a PLC-class device that records with sink = "buffer":

taktwerk record opc.tcp://10.0.0.2:4840 --dir /data/records --recorder main
  • --recorder may be left out when the engine has only one; --namespace and --prefix match the server’s namespace and the engine’s system_prefix when they are not the defaults.
  • It starts with the oldest row the engine still holds and opens the run at the first row it gets: source in run.json is the endpoint, start.utc the puller host’s clock.
  • It pulls again at once while batches come back full, else after a tenth of the engine’s buffer_s (at most 1 s). It stays lossless while it is never away longer than buffer_s.
  • A jump in the cycle numbers is written as a gap event, and so are engine events that left the engine’s log before they were pulled.
  • When the engine stops, its server stays up (at most 5 s) until every recorder pulled during the run has its last rows and events; the puller writes the stop event, the rows up to the last tick, and closes the run.
  • A lost connection is retried. When the engine restarted (engine_run changed), the run is closed and the next one opened.
  • Its parts are written the same way as a local sink’s, so the same rows give the same bytes.

Pull interface

For integrators writing their own puller. The engine’s OPC UA server adds per recorder, next to the counters, in the signal namespace:

  • <prefix>.recorder.<id>.manifest, a String variable: run.json without the run fields (run_id, host, source, start, end), as JSON.
  • <prefix>.recorder.<id>.read_rows(from_cycle: UInt64, max_rows: UInt32) returns engine_run (String), oldest_cycle, next_cycle (UInt64) and rows (ByteString). Rows start at the first row at or after from_cycle still held, 0 meaning the oldest. Each row is its cycle and then one word per column word, all little-endian u64: a float’s bits (f32 in the low 32), an integer sign- or zero-extended, a bool 0 or 1, a text byte per word. A reply holds at most 8 MiB. Ask again from next_cycle; a jump in the cycles is a gap.
  • <prefix>.recorder.<id>.read_events(from_seq: UInt64, max: UInt32) returns engine_run, oldest_seq, next_seq, then cycles (UInt64[]), kinds, sources and details (String[]), one entry per event, at most 4096 per call.

The methods are called on the recorder’s folder object, NodeId s=<prefix>.recorder.<id>/. A changed engine_run means the engine restarted and its cycles count from 0 again.

Simulation runs

The engine that runs a project on a controller in real time also runs it as a simulation: the same project, the same model packages, the same fixed-step semantics, as fast as the models compute. taktwerk solves no equations itself. Each model advances itself by one step at every tick it is due, and the engine exchanges values at tick boundaries, as in real time.

Pace

--speed decides how ticks follow the wall clock:

taktwerk run project.toml                  # real time: one tick per tick_ms
taktwerk run project.toml --speed 120      # deadlines 120 times closer together
taktwerk run project.toml --speed max --no-connectors --cycles 100000
speedticksengine clockoverruns
1on absolute deadlines every tick_mswall clockcounted
<factor>on absolute deadlines every tick_ms / factorengine timecounted
maxeach as soon as the previous one is doneengine timenone

Model time is start_time + tick × tick_ms at every speed; a model sees the same step size and the same inputs. What changes is how long a tick takes on the wall clock.

Engine time. Off real time the engine’s clock is engine time: an input’s age is measured in model time, and a write by a connector (a tunable set from the TUI, say) is stamped with the engine time of the tick it lands in. So max_age_ms means the same at every speed.

Recorders lose no rows at max. In a paced run a file sink that falls a ring behind loses rows (see Recording); unpaced, nothing is late, so the cycle waits for its file sinks instead. A buffer sink is not waited for.

Connectors. --no-connectors starts none: the run serves nothing and binds no port, so many runs can share a machine. An opcua-client exchanges values with a device in wall time and is refused off real time. The OPC UA server may stay; a client sees the run go by at its speed and can still set tunables, which are then stamped and logged at the engine’s tick.

Same project, same inputs: the same rows, at any speed. A run whose inputs only come from its models (no connector writes while it runs) records byte-identical parts at --speed 1, 120 and max, except for taktwerk.overruns, which counts the machine’s missed deadlines.

Stop conditions

A run ends on SIGINT or SIGTERM, on a model error, or at the first of these:

taktwerk run project.toml --speed max --no-connectors \
  --cycles 1000000 --until-time 86400 \
  --stop-when 'tank.level > 2.0' --stop-when 'ctrl.alarm'
  • --cycles N: after N ticks.
  • --until-time S: before the first tick whose engine time is at or after S seconds, so the last tick is the last one before S; with start_time 0 and a 0.1 s tick, --until-time 60 runs 600 ticks.
  • --stop-when CONDITION: after the first tick at which the condition holds; that tick is the last recorded one. A condition is <signal> <op> <number> with >, >=, <, <=, == or !=, or a bare signal, which holds when the value is not zero (a flag set). name[i] takes element i of an array. true and false are 1 and 0. Any numeric signal works, read after the tick: outputs, inputs, tunables, system signals. NaN satisfies only !=. The option repeats; the first condition that holds ends the run.

Conditions are parsed against the plan at start, so a typo fails the run before the first tick. The stop event in events.csv names what ended the run: cycle limit reached, time limit reached, or condition tank.level > 2.0.

Overrides

One project serves many runs. --set, --model and --record-dir change a run without editing the project file:

  --set ctrl.kp=2.5 --set plant.tau='[0.2, 0.5]' --set plant.dims.n=2 \
  --set engine.start_time=0 --set plant.u=1.0 \
  --model plant=../packages/plant-v2 --record-dir out/run-7
keywhat it sets

  • Overrides apply in order once the models are loaded, so a later one wins, and they are checked like the project file: an unknown instance, variable or signal, an output, a wired input, or a value of the wrong shape fails the run before it starts.

Seeds

--seed N gives a run one seed, and every instance that draws random numbers its own seed derived from it:

taktwerk run project.toml --speed max --no-connectors --until-time 600 --seed 7
  • Which variable. An instance takes its seed through a numeric scalar parameter or tunable named seed, when its model has one. A model that names it differently is pointed at it in the project, seed_var = "rng_seed" on the [[instance]]; seed_var = "" takes none. A model needs no change for this: it already reads its seed from a parameter, now the run sets it.
  • Which value. Instance id gets splitmix64(N xor fnv1a(id)), reduced to what the variable holds: 31 bits for a signed 32-bit integer, 32 for an unsigned one, 53 for a float, 63 for a 64-bit integer. Instances draw independent streams, and a renamed instance draws another.
  • What wins. The run seed replaces a seed the project file sets; --set <instance>.seed=… replaces the run seed. Without --seed nothing changes.
  • Recorded. run.json’s invocation holds seed and seeds, the value each instance got.

Same project, same overrides, same seed: byte-identical parts, at any speed.

Campaigns

A campaign is a set of simulation runs of one project, planned from one file: the product of named cases, a parameter grid, random samples and replicates, each run one scenario with its own seed. taktwerk campaign prints the plan; with --write it runs it, each run a taktwerk run process of its own, and picks up where it stopped when run again.

taktwerk campaign sweep.toml            # the plan, nothing run
taktwerk campaign sweep.toml --write    # run what is not done

The campaign file

[[event]]                        # events of every run, as in a scenario file

  • Runs. The product of the axes present, in the order case, grid point, sample, replicate. A run is named by its axes: small-outlet-g3-s07, or g03 for a grid alone, run for a campaign without axes.
  • What a run runs. The common scenario file, then the campaign’s [set], [stop] and events, then the case’s scenario file and set, then the grid point’s and the sample’s values: later values win, stop conditions and events add up. The result is the run’s run.toml, a scenario file that taktwerk run --scenario reruns on its own.
  • Seeds. Run seeds derive from the campaign’s seed and the run’s sample and replicate, 63 bits of splitmix64: runs that differ only in case or grid point share their seed, so a comparison of cases or gains sees the same noise (common random numbers). A grid or sample key seed sets the run seed instead.
  • Samples. A Latin hypercube puts one draw of each variable in each of n equal-probability strata, shuffled per variable; each variable draws from its own stream of the campaign’s seed, so adding a variable leaves the others’ draws as they were. normal maps through the inverse normal distribution, choice picks one of its values.
  • Every run is checked when the plan is made: a bad case name, an empty grid, a bad distribution or a run without a stop limit fails the plan before anything runs.

Running and resuming

Each run is taktwerk run <project> --speed <speed> --no-connectors --scenario run.toml --record-dir <run directory>, jobs at a time; a library with process-wide state is no problem, since every run is its own process.

out/sweep/
  campaign.json                   the plan: file and project hashes, every run's values, seed, spec hash
  runs.csv                        one row per run: axes, seed, status, stop, cycles, wall time, values
  runs/small-outlet-g3-s07/
    run.toml                      the run's scenario
    status.json                   status, exit code, stop, cycles, wall time, sha256 of every record file
    stderr.log                    the run's log
    project/main/<run-id>/        the run's records: run.json, parts, events.csv
  • Status. A run is ok when it exits cleanly on a limit or a condition, failed otherwise; a run stopped by SIGINT or SIGTERM is not ok.
  • Resume. --write again runs only what is not done: a run is done when its status.json says ok and its spec hash is the planned one. The spec hash covers the taktwerk version, the project file, the project’s model packages and the run’s scenario, so a changed project or a rebuilt package runs everything again. An interrupted or failed run’s directory is cleared and run again.
  • Another plan. When the output already holds a plan with other runs, --write refuses; --force clears the runs and starts over.

runs.csv and campaign.json are made to be read back: the Python reader loads a campaign into a table of runs and each run’s signals into arrays.

Workbench

The workbench is a web UI over a project folder, and the same UI over one running engine. A build with the ui feature carries it (cargo install taktwerk --features ui); the desktop app in desktop/ wraps it.

A project folder

taktwerk serve examples/campaign
# taktwerk workbench: http://127.0.0.1:8470/#token=…

Open the printed URL. The token in it lets the page start and stop runs and write values; serve listens on loopback only.

  • Project: the folder’s project, scenario, campaign and model files; a project’s plan as check resolves it (instances, signals with units, recorders, connectors) or its problems.
  • Runs: start a project with a scenario, speed, stop, seed, overrides and a record directory. A run starts without the project’s own connectors unless asked, so it talks to no PLC by accident. Each run serves an HTTP API on a free loopback port that serve proxies; stop ends it as SIGTERM would.
  • Live: status, cycle, heartbeat and counters; every signal with its value, unit and age; trends of the signals picked, one chart per unit; inputs and tunables written in place; the event log.
  • Records: every run recorded below the folder; a run’s metadata, overrides, events and columns plotted (long runs thinned to a minimum and maximum per bucket); a second run overlaid dashed, with the largest difference per column.
  • Campaigns: each campaign’s runs with their values, status, stop and wall time; up to eight runs plotted together; two runs compared in the records view.

One engine

An engine with an http connector serves the live view itself, on a PC or a PLC:

taktwerk run plant.toml --http 127.0.0.1:8480 --http-writes

Writes need the token the connector writes to its token file (see HTTP API); the page asks for it on the first write.

Real time

[engine.realtime] applies to the cycle thread only:

[engine.realtime]
policy = "fifo"       # SCHED_FIFO; or "rr"
priority = 80         # 1..=99, at most the unit's LimitRTPRIO
cpu = 3               # pin the cycle thread
lock_memory = true    # mlockall before the first tick

What each setting needs:

settingneeds
policy, priorityLimitRTPRIO ≥ priority, or CAP_SYS_NICE
lock_memoryLimitMEMLOCK=infinity, or CAP_IPC_LOCK

If a setting is refused the engine does not start. A dedicated CPU helps most when nothing else runs on it: keep it free of other work (isolcpus= on the kernel command line, or a cpuset), start the process on the other CPUs with the unit’s CPUAffinity=, and let cpu pin the cycle thread to the free one. Measure on the target: taktwerk run prints the mean and longest tick and the overrun count when it stops, and taktwerk.overruns is live on the OPC UA server.

Cross-building

taktwerk runs on aarch64, x86_64 and 32-bit hard-float ARM (armv7) Linux. Build on a development machine for the target with cargo-zigbuild, which links against an older glibc than the host’s so one binary runs on older target systems:

cargo install --locked cargo-zigbuild      # also needs `zig` on the PATH
rustup target add aarch64-unknown-linux-gnu x86_64-unknown-linux-gnu armv7-unknown-linux-gnueabihf

# The suffix after the target is the glibc version to link against: the oldest your targets run.
cargo zigbuild --release -p taktwerk --target aarch64-unknown-linux-gnu.<glibc>
cargo zigbuild --release -p taktwerk --target x86_64-unknown-linux-gnu.<glibc>
cargo zigbuild --release -p taktwerk --target armv7-unknown-linux-gnueabihf.<glibc>

The binaries land in target/<target>/release/taktwerk. taktwerk has no native dependencies beyond libc; its OPC UA security is pure Rust.

Model libraries are separate files and must run on the target too: build raw libraries per architecture into lib/aarch64/, lib/x86_64/ and lib/arm/ (zig cc -target aarch64-linux-gnu.<glibc> or arm-linux-gnueabihf.<glibc> works for C), and ship FMUs with a binary for the target platform (see FMI 3).

pi.c:

#include <stdlib.h>
#include "pi.h"

typedef struct {
    int n;
    double dt;
    double integral[];
} pi_state;

int pi_init(void **handle, int n, double dt) {
    pi_state *s;
    int i;
    if (n < 1 || dt <= 0.0) return -1;
    s = malloc(sizeof *s + sizeof(double) * (size_t)n);
    if (!s) return -2;
    s->n = n;
    s->dt = dt;
    for (i = 0; i < n; i++) s->integral[i] = 0.0;
    *handle = s;
    return 0;
}

int pi_step(void *handle, const pi_gains *gains, const double *sp, const double *pv, double *u) {
    pi_state *s = handle;
    int i;
    if (!s) return -1;
    for (i = 0; i < s->n; i++) {
        double e = sp[i] - pv[i];
        s->integral[i] += gains->ki * e * s->dt;
        u[i] = gains->kp * e + s->integral[i];
    }
    return 0;
}

void pi_terminate(void *handle) {
    free(handle);
}

#ifndef LOWPASS_H
#define LOWPASS_H

typedef struct {
    int n;              /* 1..64 = 3 */
} lowpass_dims;

typedef struct {
    const double *tau;  /* [n] s: time constant */
    const double *y0;   /* [n]: initial state */
} lowpass_params;

typedef struct {
    const double *u;    /* [n]: filter input */
} lowpass_inputs;

typedef struct {
    double gain;        /* output gain */
} lowpass_tunables;

typedef struct {
    double *y;          /* [n]: gain times the filter state */
} lowpass_outputs;

int lowpass_init(void **h, const lowpass_dims *dims, const lowpass_params *params,
                 double step_size);

int lowpass_terminate(void *h);

lowpass.c:

#include <stdlib.h>
#include "lowpass.h"

typedef struct {
    int n;
    double *alpha; /* [n], dt / (tau + dt) */
    double *x;     /* [n], filter state */
} lowpass_state;

int lowpass_init(void **h, const lowpass_dims *dims, const lowpass_params *params,
                 double step_size) {
    lowpass_state *s;
    int i;
    if (dims->n < 1 || step_size <= 0.0) return 1;
    s = calloc(1, sizeof *s);
    if (!s) return 2;
    s->n = dims->n;
    s->alpha = calloc((size_t)s->n, sizeof *s->alpha);
    s->x = calloc((size_t)s->n, sizeof *s->x);
    if (!s->alpha || !s->x) {
        lowpass_terminate(s);
        return 2;
    }
    for (i = 0; i < s->n; i++) {
        if (params->tau[i] < 0.0) {
            lowpass_terminate(s);
            return 3;
        }
        s->alpha[i] = step_size / (params->tau[i] + step_size);
        s->x[i] = params->y0[i];
    }
    *h = s;
    return 0;
}

int lowpass_step(void *h, double time, const lowpass_inputs *in,
                 const lowpass_tunables *tun, lowpass_outputs *out) {
    lowpass_state *s = h;
    int i;
    (void)time;
    for (i = 0; i < s->n; i++) {
        s->x[i] += s->alpha[i] * (in->u[i] - s->x[i]);
        out->y[i] = tun->gain * s->x[i];
    }
    return 0;
}

int lowpass_terminate(void *h) {
    lowpass_state *s = h;
    if (s) {
        free(s->alpha);
        free(s->x);
        free(s);
    }
    return 0;
}

io_model.h:

/* A model behind a single entry point: one function for init and step, called with an id and
 * two opaque byte pointers that the library casts to its input and output structs. The library
 * keeps no state; every call re-reads the sizes it reported from the caller's output struct. */
#ifndef IO_MODEL_H
#define IO_MODEL_H

#include <stdint.h>

#define IO_ID 7

#define IO_OK 0
#define IO_NULL_ARGUMENT (-1)
#define IO_UNKNOWN_VARIANT (-2)
#define IO_UNKNOWN_ID (-3)
#define IO_NOT_INITIALISED (-4)
#define IO_BAD_FLAG (-5)

/* What a successful call writes into `ready`: a true byte that is not 1. */
#define IO_TRUE_BYTE 2

typedef struct {
    int32_t *init_flag; /* 1 on the first call (init), 0 on every step */
    int32_t variant;    /* by value between two pointers: which size set to report */
    double *k;          /* scalar gain */
    double *u;          /* nu inputs */
    int32_t *counter;   /* step counter, written back by the library */
    char *title;        /* text the caller supplies, NUL-terminated */
} io_input;

typedef struct {
    char *label;      /* the title echoed back, or the library's own name if empty */
    double *y;        /* ny outputs: y = k * gain * u */
    double *gain;     /* ny x nu, row-major, filled at init */
    double *p;        /* np parameters, filled at init */
    char *names;      /* names written at init */
    int32_t *dim_nu;  /* reported at init */
    int32_t *dim_ny;  /* reported at init */
    int32_t *dim_np;  /* reported at init */
    uint8_t *ready;   /* IO_TRUE_BYTE after every successful call */
} io_output;

int io_call(int id, char *in, char *out);

#endif

io_model.c:

#include "io_model.h"

#include <stddef.h>
#include <string.h>

static int sizes(int32_t variant, int32_t *nu, int32_t *ny, int32_t *np) {
    switch (variant) {
    case 1: *nu = 2; *ny = 3; *np = 4; return 0;
    case 2: *nu = 1; *ny = 1; *np = 2; return 0;
    default: return -1;
    }
}

static void copy_text(char *dst, size_t cap, const char *src) {
    size_t n = strlen(src);
    if (n >= cap) n = cap - 1;
    memcpy(dst, src, n);
    dst[n] = '\0';
}

int io_call(int id, char *in_bytes, char *out_bytes) {
    if (id != IO_ID) return IO_UNKNOWN_ID;
    if (in_bytes == NULL || out_bytes == NULL) return IO_NULL_ARGUMENT;
    io_input *in = (io_input *)in_bytes;
    io_output *out = (io_output *)out_bytes;
    if (in->init_flag == NULL || in->k == NULL || in->u == NULL || in->counter == NULL ||
        out->y == NULL || out->gain == NULL || out->p == NULL || out->dim_nu == NULL ||
        out->dim_ny == NULL || out->dim_np == NULL || out->ready == NULL)
        return IO_NULL_ARGUMENT;
    int32_t nu, ny, np;
    if (sizes(in->variant, &nu, &ny, &np) != 0) return IO_UNKNOWN_VARIANT;

    if (*in->init_flag == 1) {
        *out->dim_nu = nu;
        *out->dim_ny = ny;
        *out->dim_np = np;
        for (int i = 0; i < ny; i++) {
            out->y[i] = 0.0;
            for (int j = 0; j < nu; j++) out->gain[i * nu + j] = (i + 1) + 0.1 * j;
        }
        for (int i = 0; i < np; i++) out->p[i] = 0.5 * i;
        if (out->label != NULL)
            copy_text(out->label, 32, (in->title != NULL && in->title[0] != '\0') ? in->title
                                                                                   : "io");
        if (out->names != NULL) copy_text(out->names, 24, "k;u;y;p");
        *in->counter = 0;
        *out->ready = IO_TRUE_BYTE;
        return IO_OK;
    }
    if (*in->init_flag != 0) return IO_BAD_FLAG;
    if (*out->dim_nu != nu || *out->dim_ny != ny || *out->dim_np != np) return IO_NOT_INITIALISED;
    for (int i = 0; i < ny; i++) {
        double acc = 0.0;
        for (int j = 0; j < nu; j++) acc += out->gain[i * nu + j] * in->u[j];
        out->y[i] = *in->k * acc;
    }
    *in->counter += 1;
    *out->ready = IO_TRUE_BYTE;
    return IO_OK;
}

read_run.py:

"""Read one recorded run with the Python standard library alone.

Usage: python3 read_run.py <run-dir>
"""

import csv
import gzip
import json
import sys
from pathlib import Path


def rows(run: Path):
    """Yield every row of the run as a dict, parts in order, header lines skipped."""
    for part in sorted(run.glob("part-*.csv.gz")):
        with gzip.open(part, "rt", newline="") as f:
            try:
                yield from csv.DictReader(f)
            except EOFError:
                pass  # the open part of a running engine ends at its last flush


def main() -> None:
    run = Path(sys.argv[1])
    meta = json.loads((run / "run.json").read_text())
    every = meta["every"]
    n, gaps, last, prev = 0, 0, None, None
    for row in rows(run):
        cycle = int(row["cycle"])
        if prev is not None and cycle != prev + every:
            gaps += 1  # rows lost between prev and cycle
        prev, last, n = cycle, row, n + 1
    print(
        f"{meta['project']}/{meta['recorder']}: {n} rows, tick {meta['tick_s']} s, "
        f"every {every}, {gaps} gaps"
    )
    print("last row:", last)
    with open(run / "events.csv", newline="") as f:
        for e in csv.DictReader(f):
            print(f"event {e['cycle']} {e['kind']} {e['source']}: {e['detail']}")


if __name__ == "__main__":
    main()

analyze.py:

"""Rank the gains of the level-loop campaign by how well each run rejects the disturbance.

    uv run --with taktwerk python examples/campaign/analyze.py examples/campaign/out/gains

For every run: the integral of the absolute level error after the disturbance step (300 s to
700 s, before the sensor freezes), the largest error in that window, and the largest error while
the sensor is frozen (700 s to 760 s) and the minute after. Per case, the runs best first.
"""

from __future__ import annotations

import sys

import taktwerk


def window(run: taktwerk.Run, start: float, end: float) -> list[int]:
    """Row indices with start <= t_engine < end."""
    return [i for i, t in enumerate(run.t_engine) if start <= t < end]


def metrics(run: taktwerk.Run) -> dict[str, float]:
    level, sp = run["plant.level"], run["ctrl.sp[0]"]
    dt = run.manifest["tick_s"]
    after = window(run, 300.0, 700.0)
    frozen = window(run, 700.0, 820.0)
    return {
        "iae": sum(abs(level[i] - sp[i]) for i in after) * dt,
        "max_err": max(abs(level[i] - sp[i]) for i in after),
        "max_err_frozen": max(abs(level[i] - sp[i]) for i in frozen),
    }


def main(out: str) -> None:
    campaign = taktwerk.read_campaign(out)
    rows = []
    for r in campaign:
        if not r.ok:
            print(f"{r.name}: {r.status}, skipped", file=sys.stderr)
            continue
        rows.append((r, metrics(r.read())))
    for case in dict.fromkeys(r.case for r, _ in rows):
        print(f"\n{case}")
        print(f"  {'run':<18} {'kp':>5} {'ki':>6} {'IAE [m s]':>10} {'max err [m]':>12} {'frozen [m]':>11}")
        for r, m in sorted((x for x in rows if x[0].case == case), key=lambda x: x[1]["iae"]):
            print(
                f"  {r.name:<18} {r.values['ctrl.kp']:>5} {r.values['ctrl.ki']:>6} "
                f"{m['iae']:>10.3f} {m['max_err']:>12.4f} {m['max_err_frozen']:>11.4f}"
            )


if __name__ == "__main__":
    if len(sys.argv) != 2:
        sys.exit(f"usage: {sys.argv[0]} <campaign output directory>")

Making a model taktwerk-compatible

taktwerk has no ABI of its own. It hosts two kinds of model:

  1. FMI co-simulation FMUs (FMI 3, also FMI 2). FMI 3 is the recommended format: any tool that exports FMI 3 co-simulation works, and structural parameters carry the sizes.
  2. Plain C shared libraries, described by a descriptor (taktwerk-model.toml) next to the library. New C models follow the recommended shape; existing other C interfaces are hosted through a hand-confirmed descriptor.

The model convention

Whatever the format, a taktwerk model is:

  • Size-generic and plant-agnostic. Variables have symbolic shapes over named dimensions (y: f64[ny], A: f64[nx, nx]) with optional min, max and default. The model learns each size at init. A fixed-size model is one whose dimensions are literals.
  • Explicit about roles. Each variable is an input (read every step), an output (written every step), a parameter (set once before init) or a tunable (set before init, changeable while running, delivered before the next step).
  • Allocation-free in its step. The engine owns every buffer the model exchanges: it sizes them at init and passes pointers that stay valid for the instance’s lifetime. A library may allocate its own state at init, never per step.
  • Honest about instances. A library that keeps state per instance (behind a handle, or in structs the engine owns per instance) declares multiple. A library with state in globals declares single; taktwerk then loads a private copy of the file for each further instance.
  • Explicit about matrix layout: row-major (C order) or column-major.
  • Fail-loud. A step that cannot continue returns an error code; the engine stops (fail-stop) and the service manager restarts it. Never return success with garbage outputs.

The project file then binds every dimension, sets parameters and maps signals per instance; one model serves many instances. See Concepts.

Checking a model

taktwerk inspect model.fmu --kind fmi      # or: taktwerk inspect path/to/package --kind raw

inspect prints dimensions and variables exactly as the engine sees them; it is the quickest way to confirm sizes, causalities, types and units came across.

Wrapping a raw model as an FMU

A confirmed package can also leave taktwerk as a standard FMI 3 co-simulation FMU, for any importer:

taktwerk fmu-wrap path/to/package --write -o model.fmu  # build for the host
taktwerk fmu-wrap path/to/package --target aarch64 --target x86_64 --write   # cross-build with zig

fmu-wrap builds for aarch64 and x86_64.

The generated C wrapper does what the raw adapter does, in C: it allocates the buffers from the bound structural parameters (one UInt64 per dimension, with the descriptor’s min, max and default as start), starts every input, parameter and tunable at the descriptor’s start (zero without one), fills the struct members per call, loads the library itself (a single library as a private copy per instance), checks ok_codes and reported lengths. The structs are emitted for the target compiler and checked against taktwerk’s layout at compile time. Text buffers appear as String variables; a library told its step size (builtin = "step_size") is initialised on the first fmi3DoStep, which fixes the communication step. The FMU carries the library and any --bundled dependency under binaries/<arch>-linux/ and the wrapper source under sources/.

FMI 3 (recommended)

taktwerk runs FMI 3 and FMI 2 co-simulation FMUs. Export from any tool that writes FMI 3 co-simulation for Linux; the FMU then runs unchanged in taktwerk and in every other FMI importer. A kind = "fmi" model path is an .fmu archive (extracted to a private temporary directory at load) or an already extracted FMU directory.

Calling sequence

Per instance: instantiate (co-simulation, no event mode, the FMU’s resources/ directory as resource path), configuration mode for structural parameters, parameters set, initialization mode at engine.start_time (no tolerance, no stop time) with the inputs described under Init, outputs read back, then one DoStep per period of every × tick_ms. Inputs are set before every step, changed tunables before the next step; outputs are read after it. OK and Warning are success; any other status, or a step that requests termination, stops the engine. Logging goes to the engine log at debug level.

Without the flag, all instances share one loaded library. Prefer FMUs that keep all state in the instance.

The recommended shape

New C models use this shape, for a model <m>:

typedef struct { int nx; /* 1..64 = 4 */ int nu; } <m>_dims;   /* one int per dimension */
typedef struct { const double *A; /* [nx][nx] */ double k; } <m>_params;
typedef struct { const double *u; /* [nu] m/s: inflow */ } <m>_inputs;
typedef struct { double gain; } <m>_tunables;
typedef struct { double *x; /* [nx] */ double y; } <m>_outputs;

int <m>_init(void **h, const <m>_dims *dims, const <m>_params *params, double step_size);
int <m>_step(void *h, double time, const <m>_inputs *in, const <m>_tunables *tun,
             <m>_outputs *out);
int <m>_terminate(void *h);   /* or void */

taktwerk import-header reads a header in this shape completely and writes a descriptor that is already confirmed: nothing is guessed, so there is nothing to review. The rules:

  • Return codes. init and step return int; 0 is success, anything else an error. A failed init or step stops the engine (fail-stop); the code is logged. terminate returns int or void.
  • Roles by struct name. The suffix of the type name says what a struct holds: _dims, _params, _inputs, _tunables, _outputs. Every member is a variable of its struct’s role. <m>_params and <m>_tunables may be left out, and with them their argument; so may <m>_dims when no shape names a dimension. The struct arguments may come in any order; the handle, time and step_size are where the shape puts them.
  • Sizes in <m>_dims, one int per dimension, named like the dimension. A trailing comment may bound it and give a default: /* 1..64 */, /* 1.. */, /* 1..64 = 4 */.
  • Arrays are pointers whose memory the engine owns. Every pointer member carries its shape in a trailing comment on its line, in dimension names or literal lengths: /* [n] */, /* [nx][nu] */, /* [3] */. Matrices are row-major. Pointers stay valid for the instance’s lifetime, so init may keep them.
  • Scalars by value inside the structs: a scalar parameter, input, tunable or output is a plain double (or another admitted type) member without a shape.
  • Units and descriptions may follow the shape in the same comment: /* [n] s: time constant */ is unit s and description time constant; /* [n]: input */ only a description. Without a colon, one word is a unit (/* m */) and more words a description.
  • const marks what the model reads: dims, params, inputs and tunables are const; outputs are not.
  • State behind the handle. init allocates the instance’s state and stores it through h; step and terminate receive it. No globals, so any number of instances share one loaded library (instances = "multiple").
  • No allocation in step, no blocking I/O, no printing. Allocate everything at init and free it in terminate.
  • Admitted C types: double, float, bool, char, and the fixed-width and plain integer types at their 64-bit Linux widths, each optionally const and optionally followed by one *. A char * with a literal length (/* [32] */) carries text, NUL included.

step advances from time by step_size. The engine fills in and tun before each step and reads out after it; a changed tunable is in tun from the next step on.

Example: a low-pass filter bank

A first-order low-pass filter per channel over n channels, y = gain · x, with x ← x + α (u − x) and α = dt / (tau + dt).

This is examples/raw-filter-bank. lowpass.h:

/* A bank of first-order low-pass filters over n channels, in the recommended shape. */
#ifndef LOWPASS_H
#define LOWPASS_H

typedef struct {
    int n;              /* 1..64 = 3 */
} lowpass_dims;

typedef struct {
    const double *tau;  /* [n] s: time constant */
    const double *y0;   /* [n]: initial state */
} lowpass_params;

typedef struct {
    const double *u;    /* [n]: filter input */
} lowpass_inputs;

typedef struct {
    double gain;        /* output gain */
} lowpass_tunables;

typedef struct {
    double *y;          /* [n]: gain times the filter state */
} lowpass_outputs;

int lowpass_init(void **h, const lowpass_dims *dims, const lowpass_params *params,
                 double step_size);
int lowpass_step(void *h, double time, const lowpass_inputs *in,
                 const lowpass_tunables *tun, lowpass_outputs *out);
int lowpass_terminate(void *h);

#endif

lowpass.c:

#include <stdlib.h>
#include "lowpass.h"

typedef struct {
    int n;
    double *alpha; /* [n], dt / (tau + dt) */
    double *x;     /* [n], filter state */
} lowpass_state;

int lowpass_init(void **h, const lowpass_dims *dims, const lowpass_params *params,
                 double step_size) {
    lowpass_state *s;
    int i;
    if (dims->n < 1 || step_size <= 0.0) return 1;
    s = calloc(1, sizeof *s);
    if (!s) return 2;
    s->n = dims->n;
    s->alpha = calloc((size_t)s->n, sizeof *s->alpha);
    s->x = calloc((size_t)s->n, sizeof *s->x);
    if (!s->alpha || !s->x) {
        lowpass_terminate(s);
        return 2;
    }
    for (i = 0; i < s->n; i++) {
        if (params->tau[i] < 0.0) {
            lowpass_terminate(s);
            return 3;
        }
        s->alpha[i] = step_size / (params->tau[i] + step_size);
        s->x[i] = params->y0[i];
    }
    *h = s;
    return 0;
}

int lowpass_step(void *h, double time, const lowpass_inputs *in,
                 const lowpass_tunables *tun, lowpass_outputs *out) {
    lowpass_state *s = h;
    int i;
    (void)time;
    for (i = 0; i < s->n; i++) {
        s->x[i] += s->alpha[i] * (in->u[i] - s->x[i]);
        out->y[i] = tun->gain * s->x[i];
    }
    return 0;
}

int lowpass_terminate(void *h) {
    lowpass_state *s = h;
    if (s) {
        free(s->alpha);
        free(s->x);
        free(s);
    }
    return 0;
}

When the header deviates

A header that is not completely in the shape gets the heuristic proposal of other C interfaces, written with abi.confirmed = false, which the engine refuses to load. Its leading comment lists every deviation from the shape first, then every guess. Leave out the shape comment of tau, for example:

# - not the recommended shape: lowpass_params: tau is a pointer without a shape comment such as `/* [n] */`

Either fix the header and import again, or review the proposal, fix causalities and shapes by hand and set confirmed = true. That flag states that you checked which pointer takes which dimension: lengths are never inferred at run time, and a wrong shape means the library reads or writes out of bounds.

Other C interfaces: the descriptor

An existing C library that does not follow the recommended shape is hosted as it is, through a descriptor that says how to call it. The engine owns every buffer, lays structs out by C’s rules for the running target, fills pointers once per call and copies inputs in and outputs out around each step.

Workflow

  1. taktwerk import-header model.h -o taktwerk-model.toml proposes a descriptor. The importer reads flat typedef struct { … } Name; blocks and function prototypes over the admitted types; it is not a C parser (no macro expansion) and skips, with a note, anything it does not cover. A header in the recommended shape comes out confirmed; any other gets a proposal whose notes start with what deviates from that shape.
  2. Read the notes at the top of the proposal. Function roles (init, step, terminate), dimension members and pointer→length relations are guessed by name; every guess is listed. Pointers are inputs when const and outputs otherwise; scalars by value are parameters unless the struct name hints otherwise.
  3. Fix causalities (which values are parameters, which tunables), shapes, matrix layouts (the importer proposes one dimension per pointer), dimension bounds and defaults.
  4. Set abi.confirmed = true. An unconfirmed descriptor is refused at load.
  5. Put the library at lib/<arch>/ next to the descriptor and run taktwerk inspect <dir> --kind raw.

Calls

A library is called through at most three functions, or one function serving as both init and step (see single entry point):

  • [abi.init] once per instance, in declared order, after the engine has allocated and filled the buffers (dimension lengths, parameters, tunables, inputs as described under Init);
  • [abi.step] once per step, after inputs and changed tunables were copied in; outputs are copied out afterwards;
  • [abi.terminate] (optional) once when the instance is released, also after an error.

Each function returns int (returns = "int", the default), where any value in ok_codes (default [0]) is success and anything else fails the call, or void (returns = "void"). Arguments are listed in C order; each is exactly one of:

Structs

A struct in [abi.structs.<s>] lists its members with their C type in declaration order; each member maps to at most one of:

  • A scalar member mapped to a variable carries the value: inputs, parameters and tunables are written before each call, outputs read after it. A shaped variable needs a pointer member.
  • A pointer member may point at a scalar variable of any causality. One the library writes back (a counter in an input struct) is mapped to an output variable, whose buffer the engine never overwrites.
  • A pointer member carrying a dim, const or phase points at engine-owned storage.
  • Unmapped pointer members are NULL, unmapped scalars zero.

A variable member’s C type must match the variable’s type, with one exception: a uint8_t or uint8_t * member may carry a bool variable; the engine keeps the bytes and reads any non-zero byte as true.

Reported lengths. A dim member with reported = true is a length the library knows and writes itself. It is zeroed before init, then compared with the bound length after init and after every step; a difference fails the call with both values. The check runs after the call returned, so a library loaded with the wrong sizes may already have written at its own size: every reported dimension therefore needs a max, and the engine allocates each buffer shaped by it at that max while exchanging only the bound length (text and byte buffers keep their literal capacity). The project file stays the size authority.

Library-owned outputs. Some libraries allocate their output buffers themselves at init and store the addresses into the output struct’s pointer members (out->y = y_buf;), then write only their own buffers. Mark such a member owner = "library":

{ name = "y", type = "double *", variable = "y", owner = "library" }

The engine writes NULL into the member before init and never writes it again. After init and after every step it reads the address from the struct and copies the variable’s bound length (text and byte buffers: their literal capacity) from there into its own buffer, byte-wise, so the address needs no alignment. A member still NULL after init, or set back to NULL by a step, fails that call with the library left <struct>.<member> NULL. Only a pointer member mapped to an output variable can be library-owned, and no other member or argument may carry that variable. The engine trusts the address: the library must keep at least the bound length readable there for the instance’s lifetime, the same contract as every pointer the engine hands it. The default, owner = "engine", is the engine’s buffer as above.

Text is a char * member mapped to a u8 variable with a literal shape, its capacity with the terminating NUL included (shape = [32]). Such a variable is marked text: the image and the library see its bytes, while connectors, check, inspect and the TUI present a string (the OPC UA server a String node, see Connectors). A uint8_t * or unsigned char * member stays a byte buffer. The caller supplies text through a parameter (a TOML string in the project file) or an input; the library writes it into an output. Each instance owns one image per struct, the same in every call, so a library may keep a struct pointer it got at init.

C types

Admitted are double, float, bool, char and the fixed-width and plain integer types at their 64-bit Linux widths (int is i32, long and size_t are 64-bit, char is a byte that marks text), each optionally const and optionally followed by one *. Pointers to pointers are refused, except the void ** of handle = "out".

An input, parameter or tunable may declare the value it starts at, as FMI’s start does:

  • A scalar takes one number, a bool variable true or false. Integers convert to floats, floats never to integers.
  • An array takes one value for every element, or a flat list of the bound length, in the variable’s layout. A literal shape is checked at load, a symbolic one by check and at init.
  • Outputs and text variables take no start.
  • What sets a value wins over start: --set, then a scenario’s overrides, then the project’s parameters. Without any of them a value starts at start, without one at zero.
  • A tunable shows its start in the image from the beginning and keeps it until written. An external input holds its start until a connector writes it; that is not a write, so an input with an age limit stays stale until then. A wired input takes its producer’s output.
  • fmu-wrap writes start as the FMI start (a list must fit the dimensions’ defaults) and fills the wrapper’s buffers with it, so an FMU importer starts where the raw adapter does.
  • import-header proposes none; a header carries no start values.

[[variables]]name, causality (input, output, parameter, tunable), type, shape (dimension names or literal lengths; empty for a scalar), layout (row-major default, or column-major), optional unit, description, text (implied by a char * member), start (see Start values)
abi.confirmedtrue once the developer checked every pointer→length relation
abi.libraryfile name in lib/<arch>/; default: the only .so there
abi.ok_codessuccess return values of int calls; default [0]

abi.structs.<s>.membersname, type (C spelling), at most one of variable (with optional owner: engine default, or library), dim (with optional reported), builtin, const, phase

A single library keeps its state in globals, so each further instance loads a private copy of the file; a multiple library carries its state behind a handle or inside a struct the engine owns per instance.

Single entry point

A common legacy style exports one function for every call, taking an integer id and two opaque pointers the library casts to its input and output structs. Which call runs is a flag the caller sets, and the library reports its own sizes at init:

typedef struct { int32_t *first; int32_t variant; double *k; double *u; int32_t *count; } io_in;
typedef struct { double *y; char *label; int32_t *n_u; int32_t *n_y; } io_out;
int model_call(int id, char *in, char *out);  /* 0 on success */

name = "single-entry"

[[dimensions]]
name = "nu"

[[dimensions]]
name = "ny"

[[variables]]
name = "k"
causality = "tunable"
type = "f64"

[[variables]]
name = "u"
causality = "input"
type = "f64"
shape = ["nu"]

[[variables]]
name = "count"
causality = "output"
type = "i32"

[[variables]]
name = "y"
causality = "output"
type = "f64"
shape = ["ny"]

[[variables]]
name = "label"
causality = "output"
type = "u8"
shape = [32]

[abi]
confirmed = true

[abi.init]
symbol = "model_call"
args = [{ const = 7, type = "int" }, { struct = "io_in" }, { struct = "io_out" }]

[abi.step]
symbol = "model_call"
args = [{ const = 7, type = "int" }, { struct = "io_in" }, { struct = "io_out" }]

[abi.structs.io_in]
members = [
  { name = "first", type = "int32_t *", phase = { init = 1, step = 0 } },
  { name = "variant", type = "int32_t", const = 1 },
  { name = "k", type = "double *", variable = "k" },
  { name = "u", type = "double *", variable = "u" },
  { name = "count", type = "int32_t *", variable = "count" },
]

[abi.structs.io_out]
members = [
  { name = "y", type = "double *", variable = "y" },
  { name = "label", type = "char *", variable = "label" },
  { name = "n_u", type = "int32_t *", dim = "nu", reported = true },
  { name = "n_y", type = "int32_t *", dim = "ny", reported = true },
]

init and step name the same symbol; the phase member first tells the two calls apart, const fills the id and a fixed variant, the library writes the step counter back through count (an output), and n_u, n_y are reported lengths checked against the instance’s bound nu and ny.

taktwerk import-header model.h --entry model_call --arg-struct in=io_in --arg-struct out=io_out imports such a header when told the entry point and the struct behind each opaque parameter; it then also guesses a flag-like integer as a phase, size-like integer pointers in an output struct as reported lengths, and a leading integer argument as a const whose value is left to the developer. Set each reported dimension’s max before confirming. A header does not say who sets an output pointer: if the library points them at its own buffers at init, add owner = "library" to those members.

A runnable package in this style, with its header, source and confirmed descriptor: examples/raw-single-entry.

Calling convention

Supported targets are aarch64, x86_64 and 32-bit hard-float ARM Linux, with the platform’s standard C calling convention. On 32-bit ARM a float or a 64-bit integer by value is refused (pass a double, or go through a pointer or struct), and long and size_t are 32 bits.

Tutorial: a single-entry library on a controller

You have a model compiled as a C shared library that exports one function for init and step, and you want it running on a Linux controller next to a PLC, stepping at a fixed period and reachable over OPC UA. This tutorial takes it there with taktwerk, from your workstation over ssh.

The library looks like this; names differ, the shape is what matters:

typedef struct { int32_t *init_flag; int32_t variant; double *k; double *u; char *title; } my_in;
typedef struct { double *y; char *label; int32_t *n_u; int32_t *n_y; } my_out;
int my_entry(int id, char *in, char *out);   /* 0 on success */

One function, an integer id, and two opaque pointers the library casts to its input and output structs. A flag in the input struct tells init from step, and the library may report its own sizes at init. examples/raw-single-entry is a complete library of this kind to practise on.

Placeholders used below:

placeholdermeaningexample
<host>the controller’s address192.168.1.10
<user>your login on the controlleradmin
<dir>a writable directory on the controller for everything here/opt/custom/taktwerk
<port>a free TCP port for taktwerk’s OPC UA server4841

1. Look at the controller

ssh <user>@<host> 'uname -m; ldd --version | head -1; ss -ltn'

Note three things: the architecture (x86_64 or aarch64), the glibc version, and which ports are taken. A controller with its own OPC UA server usually holds 4840; pick another <port>.

2. Install taktwerk on your workstation

On a Linux workstation with Rust 1.88 or newer:

cargo install --locked taktwerk
taktwerk --version

This gives you import-header, new, inspect, check and tui locally.

3. Build taktwerk for the controller

If the workstation has the controller’s architecture and a glibc no newer than the controller’s, the binary you just installed runs there too: use ~/.cargo/bin/taktwerk.

Otherwise cross-build it from the published crate with cargo-zigbuild, which links against an older glibc than the workstation’s. Name a glibc version at or below the controller’s:

cargo install --locked cargo-zigbuild        # also needs `zig` on the PATH
rustup target add x86_64-unknown-linux-gnu   # or aarch64-unknown-linux-gnu, armv7-unknown-linux-gnueabihf

curl -sSfL https://static.crates.io/crates/taktwerk/taktwerk-0.6.0.crate | tar xz
cd taktwerk-0.6.0
cargo zigbuild --release --locked --target x86_64-unknown-linux-gnu.2.35
cd ..
cp taktwerk-0.6.0/target/x86_64-unknown-linux-gnu/release/taktwerk ./taktwerk-target

Your library has the same constraint: build it for the controller’s architecture and against a glibc at or below the controller’s (zig cc -target x86_64-linux-gnu.2.35 -shared -fPIC ... works for C).

4. Make a model package

A package is a directory with the library under lib/<arch>/ and a descriptor that tells taktwerk how to call it. The header produces the descriptor:

mkdir -p mymodel/lib/x86_64
cp libmymodel.so mymodel/lib/x86_64/
taktwerk import-header my_model.h --entry my_entry \
  --arg-struct in=my_in --arg-struct out=my_out -o mymodel/taktwerk-model.toml

--entry names the one function; each --arg-struct says which struct an opaque parameter carries, by the parameter’s name in the header. The result is a proposal: it starts with notes, one per guess, and abi.confirmed = false. Go through the notes and fix the descriptor:

  • The id. The leading integer argument is a const; set the value the library expects.
  • The init flag. A flag-like member is guessed as phase = { init = 1, step = 0 }; check the values.
  • By-value members such as variant become inputs; a fixed selection is a const member instead.
  • Roles. Pointer members become inputs or outputs by their struct. A value you want to change while running without it being an input is a tunable; a member of the input struct the library writes back is an output.
  • Sizes. Give every array its shape in dimension names or literal lengths. A size the library reports at init is a reported = true dimension member; give that dimension a max, because buffers are allocated at it.
  • Output pointers the library sets. If the library allocates its own output buffers at init and stores their addresses into the output struct’s members, the header cannot show it: add owner = "library" to those members, or the outputs stay zero. A pointer left NULL after init then fails init with a message naming the member.
  • Text. A char * member is text: give its variable a literal capacity with the NUL included, shape = [32]. Text shows as a string in check, on OPC UA and in the TUI.
  • Matrices need two shape entries and their layout.

Then set abi.confirmed = true. The descriptor has every key; the example’s taktwerk-model.toml shows a confirmed one and the command that proposed it.

5. Write the project

The project file says which models run, at which period, with which sizes, and where the OPC UA server listens:

taktwerk new mymodel --kind raw --port <port> -o project.toml --write

Open project.toml and:

  • bind every dimension under [instance.dims];
  • set start values under [instance.parameters] (text as a TOML string: title = "tank 3");
  • set the server’s endpoint to opc.tcp://<host>:<port> so it listens on the controller’s network address instead of only on 127.0.0.1.

inspect, new and check load the library of the machine they run on (lib/<uname -m>/). On a workstation of another architecture, run them on the controller in step 6 instead.

taktwerk inspect mymodel --kind raw   # the interface as taktwerk reads it
taktwerk check project.toml           # load, resolve, bind; prints the signal table

6. Ship to the controller

ssh <user>@<host> mkdir -p <dir>
scp -r taktwerk-target <user>@<host>:<dir>/taktwerk
scp -r mymodel project.toml <user>@<host>:<dir>/

The model path in project.toml is relative to the project file, so keep the two side by side as they are on the workstation.

7. Run and test

On the controller:

ssh <user>@<host>
cd <dir>
./taktwerk check project.toml
./taktwerk run project.toml

check loads the library and verifies the plan without calling the model. run calls the entry once with the init phase, checks the sizes the library reported against the project, then calls it once per tick with the step phase. A non-zero return stops the engine with the code in the log.

From the workstation, in a second terminal:

taktwerk tui opc.tcp://<host>:<port>
  • The header shows status Running and a rising heartbeat; overruns should stay 0.
  • Select an input or a tunable and set a value; the outputs follow from the next tick.
  • Text signals show as strings and are edited as strings.

Any OPC UA client works the same way: every signal is a node under the namespace urn:taktwerk.

Stop the engine with Ctrl+C. It prints a summary:

cycles 5999  published 5999  overruns 0  stale 0  cycle mean 0.059 ms  max 0.073 ms

max against the tick is your margin. A process started from an ssh session usually ends when that session closes; for anything longer than a test, run it as a service.

8. Keep it running

Running in production has the systemd unit, the real-time settings (SCHED_FIFO, a CPU, locked memory) and what each needs. On a controller that also runs a PLC runtime, keep the cycle thread’s priority below the runtime’s own tasks.

To connect the model to the PLC’s variables instead of driving it by hand, add an opcua-client connector that maps signals to the PLC’s OPC UA nodes; taktwerk new writes a commented one into the project. See Connectors.

Tutorial: a gain sweep as a campaign

A controller is tuned by running its loop many times: other gains, other plants, the same disturbance. This tutorial takes the level loop of examples/campaign from one simulated hour to a campaign of 24 runs and a ranking of the gains, with the engine that would run the same loop on a controller. Everything runs on a workstation, from the repository root, with a C compiler, taktwerk and uv.

1. The loop

The plant is a tank drained through an outlet, filled by a pump and by a disturbance inflow; its level sensor adds noise from a seed. The controller is the PI of raw-pi, reading the measured level and driving the pump. Both are raw C packages; build them:

sh examples/raw-pi/build.sh
sh examples/campaign/tank/build.sh

tank.h is in the recommended shape: taktwerk import-header tank.h --shape wrote its descriptor, confirmed. Its parameter seed makes it a seeded model, nothing more is needed for seeds.

2. One run

The set point ctrl.sp is an external input; nothing writes it unless something sets it. Run an hour of engine time as fast as the models compute, without OPC UA, with a set point of 1 m:

taktwerk run examples/campaign/project.toml --speed max --no-connectors \
  --until-time 3600 --set 'ctrl.sp=[1.0]' --seed 5

36 000 ticks of 0.1 s took about half a second with a release build on a four-core aarch64 board. The recorder main wrote the run to examples/campaign/records/project/main/<run-id>/; run.json records under invocation the speed, the time limit, the override and the seed each instance got. Read it in Python:

import taktwerk

run = taktwerk.read_run("examples/campaign/records/project/main")
print(run.stop, run.seed, run["plant.level"][-1])

Run it again with --seed 5: the parts are the same bytes.

3. A disturbance

disturbance.toml is a scenario: the set point, a time limit of 20 minutes, a step of 0.2 m³/s in the disturbance inflow at 300 s, and the level sensor frozen for a minute at 700 s.

taktwerk run examples/campaign/project.toml --speed max --no-connectors \
  --scenario examples/campaign/disturbance.toml

events.csv shows each event at its tick:

cycle,t_engine,kind,source,detail
0,0.0,start,engine,2 instances: ctrl plant
3000,300.0,scenario,plant.q_dist,add 0.2 to plant.q_dist
7000,700.0,scenario,plant.level_m,fault plant.level_m hold for 60 s
7600,760.0,scenario,plant.level_m,end: fault plant.level_m hold for 60 s
12000,1200.0,stop,engine,time limit reached

The fault acts where the controller reads the sensor: the recorded plant.level_m is what the sensor produced, the controller’s input (record ctrl.pv to see it) is what it received.

4. The campaign

gains.toml sweeps ctrl.kp over 0.5 to 4 and ctrl.ki over 0.01 to 0.2, for the tank as built and for one with a smaller outlet (plant.k_out = 0.4), all over the disturbance scenario. Look at the plan first:

taktwerk campaign examples/campaign/gains.toml

runs     24 (0 done), 2 at a time, speed max

run               seed                ctrl.ki  ctrl.kp  plant.k_out  done
nominal-g00       627405149472732430  0.01     0.5      -            no
nominal-g01       627405149472732430  0.01     1.0      -            no
...

Every run has the same seed: they differ only in case and grid point, so they all see the same sensor noise and the comparison is between the gains, not between noise draws. Run it:

taktwerk campaign examples/campaign/gains.toml --write

Each run is a taktwerk run process of its own, two at a time, and lands in examples/campaign/out/gains/runs/<name>/: its run.toml (the scenario it ran), status.json (status, stop, wall time, the hash of every record file), its log and its records. runs.csv lists them all. Stop it halfway with Ctrl-C and run the same command again: what is done is skipped. Any run reruns alone:

taktwerk run examples/campaign/project.toml --speed max --no-connectors \
  --scenario examples/campaign/out/gains/runs/nominal-g08/run.toml

5. The analysis

analyze.py reads the campaign with the Python package and ranks the runs of each case by the integral of the absolute level error after the disturbance step, next to the largest error after the step and around the frozen sensor:

uv run --with taktwerk python examples/campaign/analyze.py examples/campaign/out/gains

nominal
  run                   kp     ki  IAE [m s]  max err [m]  frozen [m]
  nominal-g08          0.5    0.2      1.525       0.1859      0.5398
  nominal-g09          1.0    0.2      1.640       0.1305      0.5179
  ...
  nominal-g00          0.5   0.01     18.925       0.2446      0.0383

The strongest integral action rejects the step best and is worst while the sensor is frozen: it integrates an error that no longer changes. The sweep shows the trade-off in one table; a [sample] axis would add plant uncertainty to it, replicates other noise draws.
