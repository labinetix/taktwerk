taktwerk

Project file

One TOML file per engine is the source of truth. Unknown keys are errors. Relative paths are resolved against the project file’s directory.

[engine]
tick_ms = 10.0
input_max_age_ms = 100.0

[engine.realtime]
policy = "fifo"
priority = 80
cpu = 3
lock_memory = true

[models.pid]
kind = "raw"            # or "fmi"
path = "models/pid"     # package directory, .fmu, or extracted FMU directory

[[instance]]            # instances run in declared order
id = "loop1"
model = "pid"
every = 2               # period = every × tick_ms
dims = { n = 3, m = "from-server" }
parameters = { kp = 1.5, ki = [0.1, 0.2, 0.3] }
inputs = { y = { signal = "plant.y", max_age_ms = 50.0 }, sp = "loop1.sp" }
outputs = { u = "plant.u" }
tunables = { kp = "tuning.kp" }

[[connector]]
id = "ua"
kind = "opcua-server"

[[recorder]]
id = "main"
signals = ["loop1.*", "plant.y"]

Every key in dims, parameters, inputs, outputs and tunables must name a dimension or a variable of that causality in the model.

dims

  • n = 3: a fixed length, checked against the dimension’s min and max.
  • n = "from-server": the length is discovered at init. The model needs a one-dimensional variable of shape [n]; the engine asks each connector for the length of the external item mapped to that variable’s signal. Today the OPC UA client answers for nodes in its map.
  • Unbound: the model’s default; without one, init fails.

parameters

Start values of parameters and tunables. Unset ones keep the model’s value: the FMU’s start value, or a raw descriptor’s start, zero without one.

  • A scalar takes a number or a boolean. Integers convert to floats; floats never convert to integers.
  • An array takes nested arrays, one level per dimension, first index outermost: A = [[1.0, 0.0], [0.0, 1.0]]. The engine stores it in the variable’s layout.
  • An array also takes one flat array of the full length, taken as already stored in the variable’s layout: A = [1.0, 0.0, 0.0, 1.0].

inputs, outputs, tunables

Each maps a variable to a signal name. Unmapped variables get <instance>.<variable>. An input binding is either a signal name or a table:

inputs = { y = "plant.y" }                                   # signal only
inputs = { y = { signal = "plant.y", max_age_ms = 50.0 } }   # with an age limit

max_age_ms overrides engine.input_max_age_ms for that input. It is refused on a wired input (one some instance outputs). When several instances consume one external signal, the explicit limits they set must agree; one explicit limit wins over the default. See Concepts for wiring rules.

A one-dimensional input may instead be composed element by element from a list with one source per element, in element order:

inputs = { y = ["plc.p", "est.mu", { signal = "plc.t", max_age_ms = 50.0 }, "est.v[1]"] }
  • name is a scalar signal of the input’s type: another instance’s scalar output (wired) or an external input, created when no one else uses it.
  • name[i] is element i, counted from 0, of another instance’s one-dimensional output of the input’s type.
  • { signal, max_age_ms } sets an age limit on one external element, as above.
  • The list’s length must equal the input’s bound length. Multi-dimensional and text inputs, outputs and tunables cannot be composed.
  • The composed value is the signal <instance>.<input>, read-only, stored each time the instance is about to step (and before its init), so a connector shows what the model received. taktwerk check lists every composed input with its element sources.

A scalar input takes one element the same way, without a list:

inputs = { n_st = "mpc.u[0]" }

It is a composed input of one element, with the same rules and the same read-only signal <instance>.<input>. A name with [ or ] that is not an element of another instance’s one-dimensional output is refused: no signal name contains brackets, so it never becomes an external input or a connector’s node mapping.

All other keys belong to the connector kind; see Connectors. A project may have several connectors of one kind, for example one client per PLC.

[[recorder]]

Per-tick history of selected signals; see Recording.

keytypedefaultmeaning
idstringrequiredunique; ASCII letters, digits, _, -; names the directory, counters and pull nodes
signalslist[]patterns over signal names in column order: * any characters, ? one, a trailing [*] or [i] for the elements of a one-dimensional signal; empty: every output
everyinteger1one row every this many ticks, at the ticks divisible by it, ≥ 1
sinkstring"file""file": parts on the engine’s disk; "buffer": RAM only, pulled by taktwerk record
dirstring"records"directory of the file sink, relative to the project file or absolute
rotatetable{ size_mb = 64, hours = 24 }a part closes at whichever comes first: compressed size in MB (10⁶ bytes), engine time in hours
retaintable{ max_gb = 2, days = 30 }closed parts deleted, oldest first, beyond the recorder’s total size in GB (10⁹ bytes) or their age in days
buffer_sfloat600seconds of engine time the ring holds, for remote pulls and as the file sink’s slack
on_fullstring"drop"a full ring overwrites its oldest rows; the cycle never waits. The only value

Every number must be positive. A pattern that matches no recordable signal, an element selector that does not fit its signal, and a ring over 4 GiB are refused at check.

Changes

Everything in the project file is read at start. Structural changes (models, dimensions, wiring, connectors) need a restart. While running, only tunables change, through a connector.
