taktwerk

CLI reference

taktwerk logs to stderr. RUST_LOG sets the filter; the default is info for run and warn otherwise. Exit status is non-zero when a command fails, when check finds a problem, and when run ends on a model or connector failure.

On Windows taktwerk is a remote client: models are not loaded, so inspect and new refuse and check reports each model as a problem; run, campaign --write and agent refuse; serve offers files, records, campaign results and devices but starts no runs. device, deploy, tui, record, import-header and a campaign’s plan work as on Linux.

The sections below are the program’s own --help output.

taktwerk

Fixed-step model execution engine for Linux with its own OPC UA server

Usage: taktwerk <COMMAND>

Commands:
  check          Load a project, its models and connectors, resolve and bind it, print the plan
  run            Run a project until SIGINT or SIGTERM
  campaign       Plan a campaign of runs from one file and print the plan; with --write run it, resuming where it stopped
  inspect        Print a model's interface: dimensions, variables, shapes
  new            Scaffold a project file for one model; prints it unless asked to write
  import-header  Read a raw model descriptor from a C header, or propose one; prints it unless asked to write
  fmu-wrap       Wrap a confirmed raw model package as an FMI 3 co-simulation FMU; a dry run unless asked to write
  tui            Monitor a running engine over OPC UA and edit its inputs and tunables
  record         Pull a recorder's rows and events from a running engine and write them as run files, until SIGINT or SIGTERM
  serve          Serve the workbench over a project folder: its files, plans, records and campaigns, runs started and watched, devices and deploys, and the web UI. Loopback only; needs a build with the `http` feature
  agent          The device side of a deploy, run over SSH: install, activate, roll back and supervise bundles under an install root. Prints one JSON document
  device         Devices reached over SSH: add, verify and scan them, and drive their bundles' units
  deploy         Deploy a bundle to a device: print the plan; with --yes install the engine, send the changed files and activate the release
  help           Print this message or the help of the given subcommand(s)

Options:
  -h, --help     Print help
  -V, --version  Print version

taktwerk check

Load a project, its models and connectors, resolve and bind it, print the plan

Usage: taktwerk check [OPTIONS] <PROJECT>

Arguments:
  <PROJECT>  Project file

Options:
      --json  Print the plan, or the problems, as one JSON object
  -h, --help  Print help

In the signal table, type is the element type, or text for a text signal; its shape is then the capacity in bytes, NUL included (text [32]). inspect prints variables the same way.

--json prints one object instead: ok, tick_s, start_time, instances (with each port’s signal and a composed input’s element sources), signals (id, name, direction, type, shape, unit, max age), recorders and connectors. A project that does not check prints {"ok": false, "problems": [...]} and exits non-zero.

taktwerk run

Run a project until SIGINT or SIGTERM

Usage: taktwerk run [OPTIONS] <PROJECT>

Arguments:
  <PROJECT>  Project file

Options:
      --cycles <CYCLES>        Stop after this many ticks
      --speed <SPEED>          How fast ticks follow the wall clock: `1` real time, `<factor>` that many times faster, `max` as fast as the models run. Off real time, ages count engine time [default: 1]
      --no-connectors          Start no connector: the run serves nothing and needs no port
      --until-time <SECONDS>   Stop before the first tick at or after this engine time, seconds
      --stop-when <CONDITION>  Stop after the first tick at which this holds: `<signal> <op> <number>`, the op one of `>`, `>=`, `<`, `<=`, `==`, `!=`, or a bare signal for "not zero"; `name[i]` for an element. Repeatable; the first that holds ends the run
      --set <KEY=VALUE>        Override before the run: `<instance>.<parameter|tunable|input>=<value>`, `<instance>.dims.<dim>=<n>`, `<instance>.every=<n>`, `engine.<tick_ms|start_time| input_max_age_ms>=<value>` or `<signal>=<value>` for a tunable's or external input's signal. The value is TOML (`0.5`, `true`, `[1, 2]`, `"text"`), else text. Repeatable, applied in order; each is recorded in run.json
      --model <ID=PATH>        Use this package or FMU for model `ID`, of the same kind. Repeatable
      --record-dir <DIR>       Write every file recorder under this directory instead of its `dir`
      --seed <SEED>            Run seed: every instance whose model has a `seed` parameter or tunable (or the one its `seed_var` names) gets its own seed derived from it; `--set` still wins
      --scenario <FILE>        A scenario file: timed events (set, add, ramp, fault, clear), overrides, stops and a seed. Options given here win over the file's
      --http <ADDR>            Serve the HTTP API and web UI on this address (`127.0.0.1:8480`), as an `http` connector added to the project's; also with --no-connectors. Needs a build with the `http` feature
      --http-writes            Let the --http connector accept writes and stop, with its token
  -h, --help                   Print help

--cycles N stops after N ticks and logs a stop event cycle limit reached; two runs of a deterministic project record the same parts (see Recording). --speed and --no-connectors run the project as a simulation, --until-time and --stop-when end it, --set, --model and --record-dir change it without editing the project, --seed seeds its models, --scenario scripts what happens while it runs; see Simulation runs. check lists each recorder with its ring size.

taktwerk fmu-wrap

Wrap a confirmed raw model package as an FMI 3 co-simulation FMU; a dry run unless asked to write

Usage: taktwerk fmu-wrap [OPTIONS] <PACKAGE>

Arguments:
  <PACKAGE>
          The raw model package (directory with `taktwerk-model.toml` and `lib/<arch>/`)

Options:
  -o, --output <OUTPUT>
          The `.fmu` to write; default `<modelIdentifier>.fmu` in the working directory

      --target <ARCH>
          Target architecture (`aarch64`, `x86_64`), repeatable; default the host.

          Another target needs `zig` on PATH (`zig cc -target <arch>-linux-gnu.2.25`) and the package's library for it.

      --bundle <LIB>
          A further library to ship beside the model's, repeatable.

          A bare file name is taken from the package's `lib/<arch>/` per target, a path is copied as is; both land in `binaries/<arch>-linux/`.

      --write
          Build and write the FMU instead of printing what it would contain

  -h, --help
          Print help (see a summary with '-h')

taktwerk tui

Monitor a running engine over OPC UA and edit its inputs and tunables

Usage: taktwerk tui [OPTIONS] <ENDPOINT>

Arguments:
  <ENDPOINT>  The engine's server, e.g. `opc.tcp://127.0.0.1:4840`

Options:
      --namespace <NAMESPACE>  Namespace URI of the signal nodes [default: urn:taktwerk]
      --prefix <PREFIX>        The engine's `system_prefix` [default: taktwerk]
  -h, --help                   Print help

Text signals show quoted ("tank 3") and are edited as strings: type the text, or quote it to keep leading or trailing spaces; inside quotes \", \\, \n and \t are escapes. The server refuses text longer than the signal’s capacity − 1 bytes.

taktwerk serve

Serve the workbench over a project folder: its files, plans, records and campaigns, runs started and watched, devices and deploys, and the web UI. Loopback only; needs a build with the `http` feature

Usage: taktwerk serve [OPTIONS] [DIR]

Arguments:
  [DIR]  The project folder [default: .]

Options:
      --listen <LISTEN>  Address and port to listen on [default: 127.0.0.1:8470]
  -i, --identity <FILE>  A private key file to log in to devices with (repeatable); default: an SSH agent's identities, then `~/.ssh/id_ed25519`, `id_ecdsa`, `id_rsa`
  -h, --help             Print help

Serves the workbench: the web UI and an API over the project folder (its project, scenario and campaign files, check --json, run records and campaign results) and runs started from it. Each run is a taktwerk run --no-connectors child (connectors only when asked) with an http connector on a free loopback port, proxied under /api/runs/<id>/live/. It prints the URL with a token; starting, stopping and writing need that token, TAKTWERK_SERVE_TOKEN when set. POST /api/shutdown with the token stops its runs and exits, as SIGTERM does. Under /api/devices it works on the device registry: verify, deploy, unit commands and each deployed bundle’s engine API through SSH (see Workbench). Needs a build with the http feature, and ui for the web UI; devices need the default feature host.

taktwerk agent

The device side of a deploy, run over SSH: install, activate, roll back and supervise bundles under an install root. Prints one JSON document

Usage: taktwerk agent [OPTIONS] <COMMAND>

Commands:
  info          The system (architecture, glibc, os-release, systemd, free space) and installed bundles
  status        Bundles' releases, selected project and unit state
  manifest      A release's manifest: the active one, or the one named
  activate      Verify the upload in `bundles/<bundle>/staging/<hash>`, make it a release and switch `current` to it. Refused while the bundle's unit runs
  rollback      Switch back to the release activated before the active one. Refused while the unit runs
  start         Start the bundle's engine unit (and its companions)
  stop          Stop the bundle's engine unit (and its companions)
  restart       Restart the bundle's engine unit (and its companions)
  enable        Start the bundle at boot
  disable       Do not start the bundle at boot
  logs          The last journal lines of the bundle's units
  gc            Remove releases but the active one and the most recent earlier ones, and staged uploads
  install-unit  Write the template unit `taktwerk@.service` and the bundles' companion units; needs root
  help          Print this message or the help of the given subcommand(s)

Options:
      --root <DIR>  The install root
      --yes         Apply a mutating command; without it, print the plan
  -h, --help        Print help

Run on a device by a host over SSH; each command prints one JSON document. Bundles, the manifest, the layout under --root and every command’s output are in Deploying to devices.

taktwerk device

Devices reached over SSH: add, verify and scan them, and drive their bundles' units

Usage: taktwerk device [OPTIONS] <COMMAND>

Commands:
  add           Add a device to the registry; `verify` pins its host key
  list          List the registry's devices and what their last verify found
  remove        Remove a device from the registry; nothing on the device changes
  verify        Connect, pin the host key on first use, and probe: architecture, glibc against the engine's floor, systemd, free space under the root, installed engines and bundles
  scan          List the hosts of an IPv4 subnet that answer on the SSH port, with their banner. Never logs in
  status        Bundles' releases, selected project, http address and unit state
  start         Start a bundle's engine unit (and its companions); through the device's privilege
  stop          Stop a bundle's engine unit (and its companions); through the device's privilege
  restart       Restart a bundle's engine unit; through the device's privilege
  enable        Start a bundle at boot; through the device's privilege
  disable       Do not start a bundle at boot; through the device's privilege
  logs          The last journal lines of a bundle's units
  rollback      Switch a bundle back to the release activated before the active one
  gc            Remove a bundle's releases but the active one and the most recent earlier ones
  install-unit  Write the template unit and the bundles' companion units; through the device's privilege. Needed once, and again when a release changes its companions
  tunnel        Forward a local port to a bundle's engine http connector on the device and print the URL, until SIGINT
  help          Print this message or the help of the given subcommand(s)

Options:
  -i, --identity <FILE>  A private key file to log in with (repeatable); default: an SSH agent's identities, then `~/.ssh/id_ed25519`, `id_ecdsa`, `id_rsa`. A password is asked for when none is accepted
  -h, --help             Print help

Devices live in devices.toml in the config dir (TAKTWERK_CONFIG_DIR overrides). add, remove and verify change only that file. Every other command connects over SSH, refuses a host key other than the pinned one and calls the agent of the device’s engine (this version if installed, else the newest). Mutating commands (start, stop, restart, enable, disable, rollback, gc, install-unit) print the agent’s plan without --yes; --yes is refused when CI is set. --json prints the agent’s report, the device or the scan result. Login, host keys, privilege, verify, scan and the tunnel are in Deploying to devices.

taktwerk deploy

Deploy a bundle to a device: print the plan; with --yes install the engine, send the changed files and activate the release

Usage: taktwerk deploy [OPTIONS] --device <DEVICE> <BUNDLE>

Arguments:
  <BUNDLE>  The bundle folder (with `taktwerk-bundle.toml`)

Options:
      --device <DEVICE>  The device, by its name in the registry
      --engine <FILE>    The engine binary to install when the device lacks this version; default: the `TAKTWERK_ENGINES` directory, the desktop app's bundled engines, or this executable when it is a Linux build for the device's architecture
      --yes              Apply; without it, print the plan
      --json             Print the plan, or the report, as JSON
  -i, --identity <FILE>  A private key file to log in with (repeatable); default: an SSH agent's identities, then `~/.ssh/id_ed25519`, `id_ecdsa`, `id_rsa`. A password is asked for when none is accepted
  -h, --help             Print help

Prints the plan (engine, files to send against the active release, bytes against free space, problems) and exits non-zero when it has problems; --yes applies it. The steps are in Deploying to devices.
